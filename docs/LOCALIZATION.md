# Локализация карты

Карта поддерживает два языка: **русский** для клиентов с локалью `ruRU` и
**английский** для всех остальных (`enUS`, `deDE`, `zhCN` и т. д.).

Источник истины — русские тексты в репозитории (`map.w3x/war3map.wts`,
object data, `localization/ui/ruRU.json`). Конвейер отделяет переводимый текст
от них и собирает английскую версию. В собранной карте английский — основной
язык, а русский оригинал лежит в override `_Locales/ruRU.w3mod`:

| Что | Основа `.w3x` (любой клиент, кроме ruRU) | `_Locales/ruRU.w3mod` (клиент ruRU) |
|---|---|---|
| `war3map.wts` (object data, лобби) | английская WTS | русский оригинал |
| `war3map.w3i` (экран загрузки) | английский текст | русский оригинал |
| `Units/CommandStrings.txt` | английский overlay | русский оригинал |
| Lua `Loc()` | `MapLocale = "enUS"` | `BlzGetLocale() == "ruRU"` → `MapLocale = "ruRU"` |

Если код локали недоступен, `Loc()` сверяет `TRIGSTR_000` с русской строкой WTS:
совпала — клиент русский. Выбор повторяется на первом тике игры.

## Исходники и результаты

Исходники перевода лежат в `localization/`:

| Путь | Назначение |
|---|---|
| `localization/ui/ruRU.json` | Русский источник интерфейса, игровых сообщений и пользовательских Lua-строк |
| `localization/locales/enUS/locale.json` | Локаль, `scope_races`; `"base": true` — эта локаль становится основой `.w3x` |
| `localization/locales/enUS/ui.json` | Английские строки интерфейса |
| `localization/locales/enUS/wts.json` | Английские WTS-строки метаданных карты (лобби/загрузка) |
| `localization/locales/enUS/w3i.json` | Английские строковые литералы метаданных загрузочного экрана |
| `localization/locales/enUS/objects/*.json` | Переводы object data по расам |
| `localization/locales/enUS/overlay/Units/CommandStrings.txt` | Английские команды и сообщения об ошибках |

`localization/catalog.json` — сгенерированный инвентарь. Он не коммитится:
его можно восстановить из object data командой `extract`.

Сборка создаёт:

| Путь | Назначение |
|---|---|
| `.cache/l10n/enUS/war3map.wts`, `war3map.w3i`, `Units/CommandStrings.txt` | Английская основа (не коммитится) |
| `map.w3x/_Locales/ruRU.w3mod/*` | Копии русских оригиналов для override (не коммитится) |
| `map.w3x/_lua/monolith_split/sections/03_localization.lua` | Таблицы `ruRU`/`enUS` и функция `Loc` (коммитится) |

`map.w3x` сам не переписывается: английскую основу подставляет только
`build_localized_map.py` во временной копии карты.

## Команды

```powershell
python scripts/wc3_l10n.py extract          # пересобрать каталог
python scripts/wc3_l10n.py extract --check  # каталог соответствует object data
python scripts/wc3_l10n.py status           # покрытие по расам
python scripts/wc3_l10n.py status --all-races # аудит покрытия по всем расам
python scripts/wc3_l10n.py check            # переводы + свежесть сборки
python scripts/wc3_l10n.py build            # WTS, CommandStrings, Lua
python scripts/wc3_l10n.py build --check    # только сравнить результаты
python scripts/wc3_l10n.py fingerprint     # записать source_sha256 новых переводов
python scripts/wc3_l10n.py externalize     # вынести встроенную кириллицу object data в WTS
```

`status --all-races` и `check --locale enUS` проверяют каталог object data и
все игровые расы. Русский WTS остаётся основой карты, кроме строки версии;
сборка создаёт английскую WTS, таблицу `Loc()` и overlay `CommandStrings.txt`.

`source_hashes.json` хранит SHA-256 исходного текста каждого переведённого
object-, UI- и `CommandStrings`-ключа. После изменения исходника `check` сообщает
устаревший перевод отдельно от отсутствующего. `fingerprint` добавляет хэши
только для ключей без отпечатка и не обновляет устаревшие автоматически.
Перед обновлением отпечатка нужно пересмотреть перевод.
После проверки конкретной строки отпечаток обновляется адресно:
`python scripts/wc3_l10n.py fingerprint --refresh "A0Y0/ability/name"`.

Порядок перед упаковкой: `extract --check`, `check`, `build`. После `build`
нужно пересобрать `war3map.lua` командой `python build_map_lua.py`, если
менялись `localization/ui/*.json` или `localization/locales/*/ui.json`.

## Ключи и проверки

Ключ object-строки строится из смыслового адреса, а не только из WTS ID:
`<rawcode>/<тип>/<поле>[/<уровень>][@hd]`, например
`A0Y0/ability/ubertip/1@hd` или `h0GS/unit/ubertip`. WTS ID хранится рядом,
поэтому перевод переживает перенумерацию строк.

`check` проверяет:

- все обязательные ключи охвата переведены;
- нет устаревших ключей, которых больше нет в object data;
- одинаковый STRING не получил разные переводы в разных объектах;
- порядок и состав цветовых кодов совпадает с исходником;
- числа, `%s`/`%d`, `|n` и ссылки на данные способностей вида `<ANbf,DataA1>`
  не потеряны и не изменены;
- в переводе не осталось кириллицы;
- ключи `Loc()` в Lua определены, а ключи `ui.json` совпадают с русским источником;
- разделы и ключи `CommandStrings.txt` совпадают с базовым файлом;
- сгенерированные WTS, Lua и overlay соответствуют исходникам (`build --check`).
- все WTS-строки `war3map.w3i`, содержащие кириллицу, имеют перевод; их source hashes актуальны.

HD-строка без отдельного перевода использует перевод одноимённой SD-строки.

## Как добавить расу

1. Добавить имя расы из `docs/techtree/` в `scope_races` файла `locale.json`
   или создать отдельный файл локали для пакета.
2. Создать `localization/locales/enUS/objects/<Race>.json` с полем `translations`.
3. Запустить `status`, затем `check`; проверять полный список отсутствующих
   ключей, а не только счётчик.
4. Перевести строки пакетом и повторить `check`, `build`, `build_map_lua.py`.

Не нужно вручную править `catalog.json`, `03_localization.lua`, WTS локали или
скопированный `CommandStrings.txt`: это результаты сборки.

## Как добавить язык

Скопировать `localization/locales/enUS/` в каталог новой локали, изменить
`locale`, убрать `"base": true` (основа одна — английская), задать
`game_locales` (коды клиентов, например `["deDE"]`) и перевести `ui.json`,
`objects/*.json` и overlay. `build --locale <код>` положит файлы в
`map.w3x/_Locales/<код>.w3mod`, а таблицы `Loc()` и `GAME_LOCALES` соберутся
сами. `build_localized_map.py` пока вызывает `build` только для основы — для
дополнительной локали её `build` нужно запустить до упаковки.

## Правила для нового текста

- Текстовые поля object data — только через `TRIGSTR_`. Если правка (HiveWE,
  скрипт) записала строку прямо в запись, `check` сообщит
  `inline object text`; исправление — `python scripts/wc3_l10n.py externalize`,
  затем перевод новых ключей.
- Новый видимый текст в Lua — ключом `Loc("…")`: русский текст в
  `localization/ui/ruRU.json`, английский в `localization/locales/enUS/ui.json`.
  Автоключи — `lua.auto_` + первые 16 символов SHA-256 русского текста.
- `Loc()` и `MapLocale` разные на разных клиентах. Их результат допустим только в
  показе (сообщения, фреймы, мультиборд, имена). Нельзя сравнивать его, хешировать,
  класть в ключи таблиц или выбирать по нему ветку логики — это рассинхрон.
  Таблицы реплик, из которых выбирают `GetRandomInt`, хранят ключи, а `Loc()`
  вызывается при показе (см. `DipRpBroadcast`).

## Упаковка и игровая проверка

Релизный `.w3x` собирается только этой командой — обычный
`HiveWE_cli build-map` упакует карту без английской основы:

```powershell
python scripts/build_localized_map.py --hivewe "C:\Path\HiveWE_cli.exe" --locale enUS --out "23_Race_Forever_v1_6_NNN.w3x"
```

Команда обновляет каталог, проверяет переводы и отпечатки, генерирует файлы
локали и Lua, собирает временную копию `map.w3x` (жёсткие ссылки) с английской
основой, вызывает `HiveWE_cli build-map`, затем через StormLib сверяет SHA-256
`war3map.lua`, английской основы и файлов `_Locales/ruRU.w3mod` и проверяет, что
устаревшего `_Locales/enUS.w3mod` в архиве нет. Если `StormLib.dll` не лежит
рядом с HiveWE или в `.cache/hivewe-build/Release`, передайте `--stormlib`.

После проверки архива нужен ручной прогон на клиентах `ruRU` и не-`ruRU`:

- язык лобби, экрана загрузки, панели выбора расы и подфракций;
- подсказки юнитов, зданий, исследований и способностей нескольких рас;
- команды и сообщения об ошибках Warcraft;
- сообщения экономики, дипломатии ботов, вассалов, повторного выбора расы;
- отсутствие `TRIGSTR_` в интерфейсе;
- сетевой матч ruRU + enUS без рассинхрона.

## Найденные дефекты исходных текстов

Эти места переведены буквально, чтобы не выдумывать механику. Их нужно
исправить отдельной задачей по русским исходникам:

- `A0VI` (Повышение): `research_tip` и `research_ubertip` содержат заглушку
  «Поджог для баффа».
- `A0WM` (Волна исцеления): `ubertip/4` содержит «Улучшенные инструменты —
  уровень 3» вместо описания четвёртого уровня.
- `A0XM` (Сторожевая башня): `research_ubertip` содержит «Дополнительные
  паруса — уровень 1».
- `A0ZO`: имя «За Орду!», подсказки уровней 2–4 — «Цепная молния», а
  ubertip — «Золотая ручка». Похоже на смешение нескольких способностей.
- В текстах Stromgard используются старые цвета (`c00ff8e78`, `cffe1d700` и
  другие). Перевод сохранил их для точного соответствия исходнику; приведение
  к [палитре](UI_COLOR_PALETTE.md) — отдельный визуальный проход.

У Ледяных троллей часть подписей исследований содержит текст чужих объектов:

- `R0IG/upgrade/name/3` описывает здание Культа Сумеречного Молота;
- `R0I6/upgrade/name/5` описывает мортирный расчёт другого юнита;
- `R0I0/upgrade/ubertip/6` описывает исследование брони Орды;
- `R0EU`, `R0I4` содержат «Обучение специазированных магов»;
- `A1D7/ability/ubertip/1`, `A1FS`, `A1FR`, `A1P6`, `A1PJ` смешивают
  названия и описания разных способностей;
- `A1EE` описывает «волну воды», хотя называется «Большой шакрам»;
- `A1CE` в подсказке исследования указывает `400%` скорости боя, а в
  ubertip — 170/240/310/380%.

Перевод сохраняет эти строки по смыслу исходника, чтобы английская версия не
расходилась с русской. Исправлять нужно сами object data и Lua, после чего
перегенерировать каталог и перевод.
