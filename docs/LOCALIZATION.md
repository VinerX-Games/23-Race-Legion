# Локализация карты

Конвейер отделяет переводимый текст от object data и WTS. Русский WTS остаётся
исходным; локаль получает полную копию WTS, где заменены только явно
переведённые STRING. Непереведённые строки падают обратно в русский, поэтому
карта остаётся рабочей при постепенном заполнении перевода.

## Состояние пилота

Пилот проверяет полный вертикальный срез: две самодостаточные расы, панель
выбора расы и файл команд.

| Часть | Охват | Состояние |
|---|---|---|
| Инвентарь object data | 30 181 строка WTS, 7 типов object data и HD-таблицы | Собирается из текущих `war3map.*` |
| Stromgard (enUS) | 285/285 строк | Переведено, проверки проходят |
| Ледяные тролли Драккари (enUS) | 442/442 ключа | Переведено, проверки проходят |
| Панель выбора расы (enUS) | 26/26 ключей | Переведено |
| `Units/CommandStrings.txt` (enUS) | Все 20 разделов | Переведено |
| Остальные расы | — | Пока русский fallback; добавляются пакетами |

Пилот намеренно ограничен объектами, которые созданы картой и принадлежат
только выбранной расе. Общие и стандартные объекты, которые встречаются у
многих рас, в охват пока не входят: их перевод затрагивает несколько рас сразу
и должен выполняться отдельным общим пакетом.

## Исходники и результаты

Исходники перевода лежат в `localization/`:

| Путь | Назначение |
|---|---|
| `localization/ui/ruRU.json` | Русские строки Lua-интерфейса, вынесенные из `63_race_picker.lua` |
| `localization/locales/enUS/locale.json` | Локаль, `scope_races`, список игровых локалей |
| `localization/locales/enUS/ui.json` | Английские строки интерфейса |
| `localization/locales/enUS/objects/*.json` | Переводы object data по расам |
| `localization/locales/enUS/overlay/Units/CommandStrings.txt` | Английские команды и сообщения об ошибках |

`localization/catalog.json` — сгенерированный инвентарь. Он не коммитится:
его можно восстановить из object data командой `extract`.

Сборка создаёт:

| Путь | Назначение |
|---|---|
| `map.w3x/_Locales/enUS.w3mod/war3map.wts` | Полная английская WTS (не коммитится) |
| `map.w3x/_Locales/enUS.w3mod/Units/CommandStrings.txt` | Английский overlay (не коммитится) |
| `map.w3x/_lua/monolith_split/sections/03_localization.lua` | Таблицы `ruRU`/`enUS` и функция `Loc` (коммитится) |

## Команды

```powershell
python scripts/wc3_l10n.py extract          # пересобрать каталог
python scripts/wc3_l10n.py extract --check  # каталог соответствует object data
python scripts/wc3_l10n.py status           # покрытие по расам
python scripts/wc3_l10n.py check            # переводы + свежесть сборки
python scripts/wc3_l10n.py build            # WTS, CommandStrings, Lua
python scripts/wc3_l10n.py build --check    # только сравнить результаты
python scripts/wc3_l10n.py fingerprint     # записать source_sha256 новых переводов
```

`source_hashes.json` хранит SHA-256 исходного русского текста каждого
переведённого object-ключа. После изменения исходника `check` сообщает
устаревший перевод отдельно от отсутствующего. `fingerprint` добавляет хэши
только для ключей без отпечатка и не обновляет устаревшие автоматически.
Перед обновлением отпечатка нужно пересмотреть перевод.
После проверки конкретной строки отпечаток обновляется адресно:
`python scripts/wc3_l10n.py fingerprint --refresh "A0Y0/ability/name"`.

Порядок перед упаковкой: `extract --check`, `check`, `build`. После `build`
нужно пересобрать `war3map.lua` командой `python build_map_lua.py`, если
менялись `localization/ui/*.json` или `localization/locales/*/ui.json`.

## Ключи и проверки

Ключ object-строки строится из смыслового адреса, а не только из WTS ID:
`<rawcode>/<тип>/<поле>[/<уровень>][@hd]`, например
`A0Y0/ability/ubertip/1@hd` или `h0GS/unit/ubertip`. WTS ID хранится рядом,
поэтому перевод переживает перенумерацию строк.

`check` проверяет:

- все обязательные ключи охвата переведены;
- нет устаревших ключей, которых больше нет в object data;
- одинаковый STRING не получил разные переводы в разных объектах;
- порядок и состав цветовых кодов совпадает с исходником;
- числа, `%s`/`%d`, `|n` и ссылки на данные способностей вида `<ANbf,DataA1>`
  не потеряны и не изменены;
- в переводе не осталось кириллицы;
- ключи `Loc()` в Lua определены, а ключи `ui.json` совпадают с русским источником;
- разделы и ключи `CommandStrings.txt` совпадают с базовым файлом;
- сгенерированные WTS, Lua и overlay соответствуют исходникам (`build --check`).

HD-строка без отдельного перевода использует перевод одноимённой SD-строки.

## Как добавить расу

1. Добавить имя расы из `docs/techtree/` в `scope_races` файла `locale.json`
   или создать отдельный файл локали для пакета.
2. Создать `localization/locales/enUS/objects/<Race>.json` с полем `translations`.
3. Запустить `status`, затем `check`; проверять полный список отсутствующих
   ключей, а не только счётчик.
4. Перевести строки пакетом и повторить `check`, `build`, `build_map_lua.py`.

Не нужно вручную править `catalog.json`, `03_localization.lua`, WTS локали или
скопированный `CommandStrings.txt`: это результаты сборки.

## Как добавить язык

Скопировать `localization/locales/enUS/` в каталог новой локали, изменить
`locale` и `game_locales`, перевести `ui.json`, `objects/*.json` и overlay.
`build` сам соберёт таблицы всех найденных локалей и включит их в
`GAME_LOCALES`; для нового языка не требуется править Lua вручную.

## Упаковка и игровая проверка

Локализованные файлы должны попасть в `.w3x` как
`_Locales/enUS.w3mod/war3map.wts` и `_Locales/enUS.w3mod/Units/CommandStrings.txt`.
Полный локализованный билд запускается одной командой:

```powershell
python scripts/build_localized_map.py --hivewe "C:\Path\HiveWE_cli.exe" --locale enUS --out "dist\23_Race_Forever_enUS.w3x"
```

Команда обновляет каталог, проверяет переводы и отпечатки, генерирует WTS и
Lua, проверяет результаты и затем вызывает `HiveWE_cli build-map`. После сборки
проверьте архив: наличие этих двух путей обязательно. Затем проверьте в игре клиентом
`enUS` и клиентом `ruRU`:

- панель выбора расы и подфракций;
- подсказку выбора Stromgard;
- отряды, героев, здания, исследования и способности Stromgard;
- команды перемещения, атаки, строительства и сообщения об ошибках;
- отсутствие `TRIGSTR_` в интерфейсе и сохранение русской карты на `ruRU`.

Статические проверки не доказывают, что конкретная версия HiveWE записала
`_Locales` в архив. Также требуется проверить карту на клиентах `enUS` и `ruRU`;
это не заменяется проверкой каталогов, WTS и Lua.

## Найденные дефекты исходных текстов

Эти места переведены буквально, чтобы не выдумывать механику. Их нужно
исправить отдельной задачей по русским исходникам:

- `A0VI` (Повышение): `research_tip` и `research_ubertip` содержат заглушку
  «Поджог для баффа».
- `A0WM` (Волна исцеления): `ubertip/4` содержит «Улучшенные инструменты —
  уровень 3» вместо описания четвёртого уровня.
- `A0XM` (Сторожевая башня): `research_ubertip` содержит «Дополнительные
  паруса — уровень 1».
- `A0ZO`: имя «За Орду!», подсказки уровней 2–4 — «Цепная молния», а
  ubertip — «Золотая ручка». Похоже на смешение нескольких способностей.
- В текстах Stromgard используются старые цвета (`c00ff8e78`, `cffe1d700` и
  другие). Пилот сохранил их для точного соответствия исходнику; приведение
  к [палитре](UI_COLOR_PALETTE.md) — отдельный визуальный проход.

У Ледяных троллей часть подписей исследований содержит текст чужих объектов:

- `R0IG/upgrade/name/3` описывает здание Культа Сумеречного Молота;
- `R0I6/upgrade/name/5` описывает мортирный расчёт другого юнита;
- `R0I0/upgrade/ubertip/6` описывает исследование брони Орды;
- `R0EU`, `R0I4` содержат «Обучение специазированных магов»;
- `A1D7/ability/ubertip/1`, `A1FS`, `A1FR`, `A1P6`, `A1PJ` смешивают
  названия и описания разных способностей;
- `A1EE` описывает «волну воды», хотя называется «Большой шакрам»;
- `A1CE` в подсказке исследования указывает `400%` скорости боя, а в
  ubertip — 170/240/310/380%.

Перевод сохраняет эти строки по смыслу исходника, чтобы английская версия не
расходилась с русской. Исправлять нужно сами object data и Lua, после чего
перегенерировать каталог и перевод.
