# Аудит восьми указанных коммитов: 510 → 511

Последующее игровое сравнение: пользователь подтвердил, что вариант 512 с полным откатом `fec12de` восстанавливает движение и без ботов, и с ботами. Это уточняет приведённую ниже первоначальную статическую оценку: связь с этим коммитом подтверждена сравнением, конкретный hunk ещё не установлен. Полный последующий разбор и два частичных отката: [FEC12DE_MOVEMENT_INVESTIGATION.md](FEC12DE_MOVEMENT_INVESTIGATION.md).

Проверка 2026-10-13. Прочитаны Git diff всех восьми коммитов: ссылка пользователя и семь записей со скриншота. Локальный `origin` — `https://github.com/VinerX-Games/23-Race-Legion`; `git ls-remote origin HEAD` подтвердил доступ к GitHub и текущий HEAD `5a5494c42e0a6b2049eabcc4e58ae6ad053fa8a4`. Проверка не меняла карту и не запускала Warcraft.

## Установленная граница версий

Ссылка пользователя [53d6b95](https://github.com/VinerX-Games/23-Race-Legion/commit/53d6b95a01ed8d50128fc41991deb065db566ac9) относится к **выпуску 510**, не 511: `version.txt` меняется с 509 на 510. Более того, `war3map.lua` из этого Git-коммита побайтно совпадает с исполняемым Lua ранее проверенного архива 510 после нормализации CRLF. SHA256: `c865885c5f3c12e3e544fb5d897dc774b27dac12254d00a6fad3aec4eaec13a3`.

Семь коммитов со скриншота — весь диапазон `53d6b95..4df89dd`. Архив 511 в этом аудите не предъявлялся: выводы о 511 относятся к Git-снимку выпуска.

## Проверка сборки

| Git-снимок | Конкатенация секций совпадает с `war3map.lua` | SHA256 исполняемого Lua |
|---|---|---|
| `53d6b95` (510) | Да; совпадает также с архивом 510 | `c865885c5f3c12e3e544fb5d897dc774b27dac12254d00a6fad3aec4eaec13a3` |
| `e1eddf1` (последняя правка секций до сборки) | Нет: итоговый скрипт ещё от 510 | `c865885c5f3c12e3e544fb5d897dc774b27dac12254d00a6fad3aec4eaec13a3` |
| `83d3fbf` (сборка) | Да | `72d2091c1b4085f2dd357e89b53672cb1c83dd97a4959d06b30252ec0892dfd4` |
| `4df89dd` (511) | Да | `72d2091c1b4085f2dd357e89b53672cb1c83dd97a4959d06b30252ec0892dfd4` |

Таким образом, поиск первого проблемного **сгенерированного** скрипта среди промежуточных коммитов показал бы скачок на `83d3fbf`, даже если причина находится в `fec12de` или другой предшествующей правке секций. Для статического разделения этих изменений следует сравнивать собранные секции, а не только исторический `war3map.lua` каждого промежуточного коммита.

## Что этот диапазон исключает и что оставляет

- В перечисленных семи коммитах нет изменений бинарных unit/destructible/pathing-файлов, нового вызова создания физических объектов, нового `ShowUnit`, `SetUnitPathing` или `SetTerrainPathable` в исходных diff.
- Кэширование `CachedFilter`, новая обёртка `ForGroupDestroy`, локальный цикл `aiStart`, механики Лунного воина и изменения Наг относятся к другим, более поздним правкам. Если баг появился уже в 511, они не объясняют его первое появление.
- В частности, предыдущая гипотеза «исправление `aiStart` увеличило создание `aiu0`» не применима к этим коммитам 511: исправление цикла здесь отсутствует. Другие изменения могли косвенно улучшить работу ботов, но это отдельная гипотеза.
- `fec12de` остаётся первым кандидатом **для разделения стартовых изменений**, `e9d9b62` — вторым для изменения старого производства/скоплений. Это приоритет анализа, не доказательство их виновности.
- Снимок 511 из Git не позволяет подтвердить, что в игре возникают маленькие невидимые blockers: прямой генератор таких преград в этих коммитах не найден. Одни исправные группы/таймеры не занимают физические клетки; нужна конкретная цепочка до создания/переноса физического объекта.
