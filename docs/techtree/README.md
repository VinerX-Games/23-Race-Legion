# База зависимостей рас (дерево технологий)

Справочник для разработчиков и ИИ-агентов: что строит, обучает и исследует каждая раса, какие у объектов
способности и требования, сколько они стоят. Позволяет отвечать на вопросы о зависимостях, не разбирая
object data карты.

**Файлы генерируются, руками не править.** Источник истины — карта: object data (`war3map.w3u/w3a/w3q/w3t`,
строки из `war3map.wts`) и Lua-триггеры выбора расы. Генератор — [`scripts/export_techtree.py`](../../scripts/export_techtree.py)
поверх `HiveWE_cli describe-race`.

```bash
python scripts/export_techtree.py           # перегенерировать (~3 мин)
python scripts/export_techtree.py --check   # сверить с картой; exit 1, если база устарела
```

Нужен `HiveWE_cli` (путь в `wc3.local.json` или `HIVEWE_CLI`, см. [TOOLING_WORKFLOW.md](../TOOLING_WORKFLOW.md)).

## Обязательное правило обновления

Любое изменение, которое затрагивает зависимости или свойства объектов рас, сопровождается перегенерацией
базы **в том же коммите**:

- добавление, удаление или переименование юнита, героя, здания, способности, исследования, предмета;
- изменение списков «Строит / Обучает / Исследования / Улучшения / Способности / Способности героя»;
- изменение требований, стоимости, ОЗ, времени, пищи, горячих клавиш, числа уровней;
- изменение стартовых юнитов и стартовых технологий расы в Lua (`04_race_selection.lua`).

Порядок: внести изменение в карту → `python scripts/export_techtree.py` → `--check` показывает `OK` → закоммитить
карту вместе с `docs/techtree/`. Если генератор запустить нельзя (нет HiveWE_cli), прямо указать это в
описании коммита/PR — не править JSON руками.

## Формат

`index.json` — список рас: файл, стартовые юниты, число объектов по типам.

`races/<Раса>.json` (имя — токен триггера `Trig_Race_<Раса>[_O]_Actions`):

| Ключ | Содержимое |
|---|---|
| `start_units` | Юниты/здания, которые раса получает при выборе (из Lua) |
| `start_tech` | Технологии, выдаваемые при выборе (`SetPlayerTechResearched`) |
| `lua` | Lua-функции, где раса стартует |
| `objects` | `id` → свойства объекта |
| `edges` | Рёбра графа строками `"<от> <тип> <к>"` |

Поля объекта (присутствуют, только если не пустые): `type` (`unit`, `hero`, `building`, `upgrade`, `ability`,
`item`, `unknown` — id не найден в object data, обычно стандартная способность движка), `name` (без цветовых
кодов), `base` (базовый объект WC3), `gold`, `lumber`, `food`, `food_made`, `hp`, `time`, `hotkey`,
`levels`, `requires`, `requires_amount`, `equivalents`, `hero_level_req`, `hero`/`item` (флаги способности),
для исследований — `gold_per_level`, `lumber_per_level`, `time_per_level`; `only_required` — объект попал
в базу только как требование.

Типы рёбер: `builds`, `trains`, `researches`, `morphs-to` (улучшение здания/юнита), `has-ability`,
`hero-ability`, `requires`, `lua-starts-with`, `lua-start-tech`.

Ограничения: зависимости, создаваемые только Lua-кодом (выдача юнитов триггерами, скрытые способности,
кастомные требования), в базу не попадают, кроме стартовых. Механику способностей (урон, длительность по
уровням) смотреть в object data и подсказках. Числа уровней требований исследований — поля `requires`
и `requires1` объединены в `requires`.
