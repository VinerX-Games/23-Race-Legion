# План Lua-миграции

## Цели

1. `map.w3x` является единственной канонической картой в репозитории.
2. Исходники Lua живут внутри `map.w3x`, а не в параллельной папке.
3. `war3map.lua` собирается автоматически из исходников, а не правится вручную.
4. Проверка карты идёт через CLI и реальный клиент Warcraft III.

## Порядок работ

### 1. Каноническая сборка Lua

- Source of truth: `map.w3x/_lua/monolith_split/`
- Сборка: `python build_map_lua.py`
- Артефакт: `map.w3x/war3map.lua`
- Правило: ручные правки допускаются только в split-исходниках, не в собранном монолите.

### 2. Автотесты через клиент

- Держать цикл `probe-map -> War3Log -> probe-log -> правка`.
- Добавить отправку чат-команд из CLI, чтобы проверять `-ai`, `-raceselect` и похожие сценарии без ручного ввода.
- Отдельно наращивать сценарии: bootstrap, команды, AI, старт расы, победа/поражение.

### 3. Починка интерфейса

- Текущий блокер уже сужен до `ITexCreate fail` по UI-текстурам.
- Дальше проверять не тайминг frame API, а совместимость и размещение импортов UI-ассетов.

### 4. Смысловое разбиение кода

После стабилизации запуска и UI:

- `bootstrap`
- `ui`
- `chat_commands`
- `economy`
- `race_start`
- `ai`
- `victory`
- `utils`

Сначала нужно держать точную воспроизводимую сборку, потом вынимать доменные модули из `80_generated_runtime.lua`.

### 5. AI для всех рас

Это отдельный большой этап. Для него нужны:

- удобный сценарный запуск матчей;
- извлечение зависимостей по расам, апгрейдам и техдереву;
- автопроверки команд и развития ИИ через CLI.

### 6. Нормализация импортов

- Нужен инструментальный проход по `war3map.imp` и usages в данных карты.
- Ручной перенос импортов по папкам слишком рискован, пока CLI не умеет безопасно переписывать пути.

## Архитектурные правила

- Должна существовать только одна цепочка сборки Lua.
- Все временные решения должны быть либо тестовыми, либо быстро удаляемыми.
- Любое изменение CLI должно уменьшать слепые зоны отладки, а не просто добавлять ещё один обходной путь.
