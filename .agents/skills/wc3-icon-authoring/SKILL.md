# Иконки Warcraft III Classic

Применять для новых иконок карты. Пользователь утвердил стиль второго набора друида воргенов: крупные рисованные мазки, простые цветовые пятна, резкие блики, глубокие тени и почти чёрный фон. Первый набор отклонён из-за избыточного реализма и мелкой фактуры.

Перед генерацией посмотреть [образец пользователя](references/classic-icons.png) и [утверждённый набор](../../../art/icons/worgen-druid-v2/preview.png). Образец передавать генератору как изображение стиля; перечисление слов Warcraft III без картинки оказалось недостаточным.

Использовать встроенный image_gen согласно доступному навыку imagegen. Брать [шаблон запроса](references/prompt-template.txt), заменять SUBJECT на конкретный образ способности. Одна иконка — один запрос. [Полные утверждённые запросы](../../../art/icons/worgen-druid-v2/prompts.json) содержат примеры семени, корней, вороньей метки и луны.

- Один крупный читаемый силуэт, несколько крупных цветовых пятен; объём передавать несколькими мазками.
- Не добавлять мелкую фактуру коры, перьев, реалистичные кратеры, фотореалистичные материалы или гладкий 3D-свет.
- Генерировать рисунок без рамки, букв, хоткеев и водяных знаков; фон непрозрачный.
- Оценивать результат в размере 64×64. Большая красивая иллюстрация сама по себе не подтверждает пригодность иконки.

Для портретов юнитов отдельно задавать два изображения: модель определяет внешность, лист рисованных портретов — стиль. Крупно кадрировать голову и верх плеч; сохранять узнаваемые маску, рога, гриву и прочие детали модели. Пример запроса и оба исходных образца находятся в [наборе портрета друида](../../../art/icons/worgen-druid-portrait/README.md). Этот портрет подготовлен по запросу пользователя; его стиль ещё не проходил отдельное утверждение.

Для портретов по готовой модели пользователь хочет рисованную интерпретацию с примерно исходной детализацией: выразительные крупные мазки, узнаваемые пропорции морды и экипировка, более удачный ракурс допустим. Не копировать скриншот и его полигональные грани. Не добавлять подробную шерсть, заклёпки, шипы, новую броню или увеличенные клыки и уши. Первый набор оказался слишком подробным и далёким от моделей, второй — слишком похожим на скриншоты. Цель — середина между ними: объёмный живой рисунок с умеренной детализацией. Сопоставлять результат с моделью по внешности, а не по точному совпадению ракурса. [Первая версия](../../../art/icons/worgen-portraits/README.md) и [вторая версия](../../../art/icons/worgen-portraits-v2/README.md) — границы для сравнения, обе отклонены пользователем.

Третья попытка с отклонёнными генерациями в референсах вернулась к первому виду и также отклонена. Для нового направления рисовки использовать модель и образец пользователя, без прежних генераций в качестве эталона. [Четвёртый набор](../../../art/icons/worgen-portraits-v4/README.md) **утверждён пользователем**: запрос про круглую кисть, плавные крупные пряди и простые светотени. Его [превью](../../../art/icons/worgen-portraits-v4/preview.png) и [точные запросы](../../../art/icons/worgen-portraits-v4/prompts.json) — рабочий образец для будущих портретов. После утверждения у №2 добавлена повязка на один глаз, у №5 — рога друида. Такие характерные детали модели сохранять; локальные исправления делать по утверждённому портрету, сохраняя остальную рисовку.

Сохранять исходники и точные запросы в art/icons/<набор>/. Новые версии хранить отдельно, если замена не запрошена.

Для экспорта использовать существующий scripts/wc3_icons.py: уменьшение Lanczos до 64×64, button(), disabled(), write_blp1(). Для активных способностей нужны BTN и DISBTN; PASBTN делать для пассивных способностей по необходимости. Повторно открыть PNG и BLP, проверить декодирование и размер. Сделать компактное превью в исходном размере и с увеличением без сглаживания.

При добавлении в карту копировать BLP в map.w3x/ReplaceableTextures/CommandButtons и CommandButtonsDisabled, регистрировать точные пути в war3map.imp существующим register_imports(). Через HiveWE назначать art и researchart способностей, buffart связанных эффектов; учитывать служебные способности и скрипты повторного внедрения. Не заменять иконки старых несвязанных способностей только из-за расположения в том же слоте. Не запускать полное внедрение механик ради импорта картинок. При изменении object data соблюдать правила проверки и обновления techtree проекта.
